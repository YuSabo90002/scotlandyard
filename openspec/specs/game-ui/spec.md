## Requirements
### Requirement: React UIコンポーネント構成

アプリケーションは、React + Phaserで構成され、明確に役割が分離されていなければならない（MUST）。

#### Scenario: アプリケーション起動

- **WHEN** アプリケーションが起動される
- **THEN** Reactアプリケーションがマウントされる
- **AND** Phaser Gameインスタンスがcanvas要素内に初期化される
- **AND** メインメニューが表示される

#### Scenario: Phaserとの統合

- **WHEN** ゲームが開始される
- **THEN** Reactコンポーネント内にPhaserゲームcanvasが埋め込まれる
- **AND** PhaserはゲームボードとプレイヤーGの描画のみを担当する
- **AND** UIコントロールとゲーム情報はReactコンポーネントで表示される

### Requirement: メインメニュー

ゲーム開始前に、プレイヤー設定を行うメニュー画面を表示しなければならない（MUST）。プライベートマッチ機能を優先し、ルーム作成と参加のUIを提供しなければならない（MUST）。

#### Scenario: メニューの表示

- **WHEN** アプリケーションが起動される
- **THEN** メインメニューが表示される
- **AND** 「ルームを作成」ボタンが表示される
- **AND** 「ルームに参加」ボタンが表示される

#### Scenario: ルーム作成

- **WHEN** 「ルームを作成」ボタンをクリックする
- **THEN** 新しいゲームルームが作成される
- **AND** ルーム待機画面に遷移する
- **AND** 生成されたルームIDが表示される

#### Scenario: ルーム参加

- **WHEN** 「ルームに参加」ボタンをクリックする
- **THEN** ルームID入力フォームが表示される
- **AND** ルームIDを入力して「参加」ボタンをクリックすると、そのルームに参加する
- **AND** ルーム待機画面に遷移する

### Requirement: ルーム待機画面

ゲーム開始前に、参加プレイヤーを表示し、ルーム情報を共有できる画面を提供しなければならない（MUST）。

#### Scenario: ルーム待機画面の表示

- **WHEN** プレイヤーがルームに参加する
- **THEN** ルーム待機画面が表示される
- **AND** ルームID（6-8文字の英数字コード）が大きく表示される
- **AND** ルームIDの横に「コピー」ボタンが表示される
- **AND** 現在の参加プレイヤーリストが表示される
- **AND** 参加人数（例: 3/6人）が表示される

#### Scenario: ルームIDのコピー

- **WHEN** 「コピー」ボタンをクリックする
- **THEN** ルームIDがクリップボードにコピーされる
- **AND** 「コピーしました」という確認メッセージが一時的に表示される

#### Scenario: プレイヤー参加の通知

- **WHEN** 新しいプレイヤーがルームに参加する
- **THEN** 参加プレイヤーリストが更新される
- **AND** 参加人数が更新される
- **AND** 既存プレイヤーに通知（例: 「〇〇さんが参加しました」）が表示される

#### Scenario: ゲーム開始（ルームホスト）

- **WHEN** ルームホストが「ゲーム開始」ボタンをクリックする
- **AND** 参加プレイヤーが3人以上である
- **THEN** ゲーム画面に遷移する
- **AND** すべてのプレイヤーに役割（怪盗X/刑事）が割り当てられる
- **AND** ゲームが開始される

#### Scenario: 人数不足でのゲーム開始試行

- **WHEN** ルームホストが「ゲーム開始」ボタンをクリックする
- **AND** 参加プレイヤーが2人以下である
- **THEN** エラーメッセージ「最低3人必要です」が表示される
- **AND** ゲームは開始されない

### Requirement: ゲーム情報パネル

ゲーム中、現在の状態を表示する情報パネルを提供しなければならない（MUST）。

#### Scenario: 情報パネルの表示

- **WHEN** ゲームが進行中である
- **THEN** 以下の情報がReactコンポーネントで表示される
  - 現在のターン数
  - 怪盗Xの移動回数（記録盤のマス数）
  - アクティブなプレイヤー（誰のターンか）
  - 各プレイヤーのチケット残数
  - 怪盗Xが使用したチケット履歴
  - 次の位置公開タイミング（例: 「次回公開: 移動回数8」）

#### Scenario: 刑事視点の情報表示

- **WHEN** 刑事のターンである
- **THEN** すべての刑事の位置が表示される
- **AND** 怪盗Xの最後に公開された位置が表示される
- **AND** 怪盗Xのチケット使用履歴が表示される

#### Scenario: 怪盗X視点の情報表示

- **WHEN** 怪盗Xのターンである
- **THEN** すべての刑事の位置が表示される
- **AND** 自分の現在位置が表示される
- **AND** 自分のチケット残数が表示される

### Requirement: プレイヤー操作UI

プレイヤーは、UIを通じてゲームを操作できなければならない（MUST）。

#### Scenario: ノード選択（Phaserインタラクション）

- **WHEN** プレイヤーのターンで、Phaserキャンバス上のノードをクリックする
- **THEN** 移動可能なノードがハイライト表示される
- **AND** 選択可能なチケット種類がReact UIパネルに表示される

#### Scenario: チケット選択と移動確定

- **WHEN** React UIパネルでチケットを選択する
- **THEN** 選択されたチケットがハイライトされる
- **AND** 「移動」ボタンが有効になる
- **AND** 「移動」ボタンをクリックすると移動が実行される

#### Scenario: 無効な操作

- **WHEN** プレイヤーが移動不可能なノードを選択する
- **THEN** エラーメッセージがReact UIに表示される
- **AND** 移動は実行されない

#### Scenario: ダブルムーブカードの選択

- **WHEN** 怪盗Xのターンでダブルムーブカードボタンをクリックする
- **THEN** ダブルムーブカード使用モードに切り替わる
- **AND** 1回目の移動用チケット選択UIが表示される

#### Scenario: ダブルムーブでの1回目チケット選択

- **WHEN** ダブルムーブカード使用モードである
- **THEN** 1回目の移動用チケット（Taxi/Bus/Underground/Black）を選択できる
- **AND** チケットを選択すると「確定」ボタンが有効になる
- **AND** 選択したチケットを保有していることがバリデーションされる

#### Scenario: ダブルムーブでの1回目ノード選択

- **WHEN** 1回目のチケットを選択し「確定」ボタンをクリックする
- **THEN** 1回目の移動先ノード選択モードになる
- **AND** 1回目のチケットで移動可能なノードがハイライト表示される
- **AND** ノードを選択すると1回目の移動が実行される

#### Scenario: ダブルムーブでの2回目チケット選択

- **WHEN** 1回目の移動が完了する
- **THEN** 2回目の移動用チケット選択UIが表示される
- **AND** 保有している2回目の移動用チケット（Taxi/Bus/Underground/Black）を選択できる
- **AND** チケットを選択すると「確定」ボタンが有効になる

#### Scenario: ダブルムーブでの2回目ノード選択

- **WHEN** 2回目のチケットを選択し「確定」ボタンをクリックする
- **THEN** 2回目の移動先ノード選択モードになる
- **AND** 1回目の移動先ノードから2回目のチケットで移動可能なノードがハイライト表示される
- **AND** ノードを選択すると2回目の移動が実行され、ダブルムーブが完了する

#### Scenario: ダブルムーブ使用時の位置公開表示

- **WHEN** ダブルムーブの1回目の移動で怪盗Xの移動回数が位置公開タイミング（3, 8, 13, 18, 24）に達する
- **THEN** 1回目の移動完了後、怪盗Xの駒が一時的にPhaserボード上に表示される
- **AND** React UIに「怪盗Xが位置を公開中」というメッセージが表示される
- **AND** 数秒後（または刑事プレイヤーの確認後）、2回目の移動に進む
- **AND** 2回目の移動完了後、怪盗Xの駒は再び隠される

#### Scenario: ダブルムーブのキャンセル

- **WHEN** ダブルムーブカード使用モードでチケット選択前に「キャンセル」ボタンをクリックする
- **THEN** 通常の移動モードに戻る
- **AND** ダブルムーブカードは消費されない

### Requirement: Phaserゲーム描画

Phaserは、ゲームボードとプレイヤー駒の描画のみを担当しなければならない（MUST）。

#### Scenario: ゲームボードの描画

- **WHEN** Phaserシーンが作成される
- **THEN** ゲームボードのノード（駅）が円形で描画される
- **AND** ノード間のコネクション（路線）が線で描画される
- **AND** 交通手段ごとに異なる色で表示される（Taxi=黄、Bus=緑、Underground=赤）

#### Scenario: プレイヤー駒の描画

- **WHEN** ゲームが開始される
- **THEN** 各プレイヤーの駒がノード上に描画される
- **AND** 刑事駒は青色の円で表示される
- **AND** 怪盗X駒は黒色の円で表示される（公開ターンのみ）

#### Scenario: 移動アニメーション

- **WHEN** プレイヤーが移動する
- **THEN** Phaserで駒が移動元から移動先へアニメーションする
- **AND** アニメーション完了後、React側の状態が更新される

### Requirement: レスポンシブデザイン

アプリケーションは、デスクトップブラウザで適切に表示されなければならない（MUST）。

#### Scenario: 画面サイズ対応

- **WHEN** ブラウザウィンドウサイズが変更される
- **THEN** Reactコンポーネントは適切にリサイズされる
- **AND** Phaserキャンバスは固定サイズ（1280x720）で表示される

#### Scenario: 最小画面サイズ

- **WHEN** ブラウザウィンドウが最小サイズ（1366x768）未満になる
- **THEN** 警告メッセージが表示される
- **AND** ゲームは引き続きプレイ可能である

### Requirement: ゲーム終了とリセット

ゲーム終了時に結果を表示し、新しいゲームを開始できなければならない（MUST）。

#### Scenario: ゲーム終了

- **WHEN** 勝利条件が満たされる
- **THEN** ゲーム終了モーダルがReact UIに表示される
- **AND** 勝者（刑事側/怪盗X側）が表示される
- **AND** 「メニューに戻る」ボタンと「もう一度プレイ」ボタンが表示される

#### Scenario: もう一度プレイ

- **WHEN** 「もう一度プレイ」ボタンをクリックする
- **THEN** 同じ設定で新しいゲームが開始される
- **AND** ゲーム状態がリセットされる
